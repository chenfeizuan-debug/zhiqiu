# 知秋书源 · 发布页（次元姬 + 少年梦）

一个静态页面，两条源，三种下载：次元姬单独、少年梦单独、合并成一个 `.xbs`（三条入口）。
用户在自己手机上填自己的凭证，本机生成香色闺阁书源，不经任何服务器。

## 文件清单

| 文件 | 作用 |
|---|---|
| `index.html` | 发布页本体（纯静态，无后端、无外部请求） |
| `使用说明.md` | 给用户看的说明：注册带网址、怎么更新、每日更新看哪里 |
| `README.md` | 本文件：部署方法 + 每天要改哪一处 |
| `404.html` | 占位 404，避免 GitHub 默认页劫持 |
| `.nojekyll` | 告诉 GitHub Pages 不要按 Jekyll 处理 |

## 部署

1. 在 GitHub 建一个仓库（或复用现有仓库）。
2. 把这 5 个文件传到仓库根目录。
3. 仓库 → Settings → Pages → Source 选 `main` 分支、`/ (root)` → Save。
4. 等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

将来绑自定义域名（例如 `zq.vv9v.cn`）就在 Pages 里填 Custom domain，再把 DNS 的 CNAME 指过去。

## 每天要改的地方（只有一处）

打开 `index.html`，搜索 `var NOTICE = {`，只改这三行：

```js
var NOTICE = {
  updated: "2026-11-01",                 // 日期，页面右上角显示「更新 2026-11-01」
  text: "今天的公告正文……",              // 公告正文，纯文本，别加 HTML 标签
  log: [                                 // 更新日志，最新的放第一条
    { "date": "2026.11.01", "text": "今天改了什么" },
    { "date": "2026.10.31", "text": "昨天改了什么" }
  ]
};
```

改完保存、覆盖上传即可，不需要懂代码。页面顶部那块「公告 · 每日更新」就是它渲染出来的，用户看那一块就知道今天的口令、维护、限速情况。

不想手改 `index.html` 的话：改 `_web/notice.json`，再执行 `python _build_web.py`，会重新生成 `index.html`（本仓库的构建脚本在 `work/zq/_build_web.py`）。

## 页面怎么工作

- 纯前端。没有后端、没有接口调用、没有统计上报。
- 次元姬：把模板里 **16 处** `var JWT = ""` 槽位换成用户粘贴的 JWT。
- 少年梦：把 **16 处** `"Bearer __SND_TV__"` 与 3 处 `@js:` 单引号占位换成 Token / 手机号 / 密码。
- 合并：两份对象合成 3 个别名（次元姬、次元姬漫画、少年梦）后整体加密。
- 加密：BTEA / XXTEA，密钥为 `香色闺阁金涛` 的 UTF-8 字节，与香色闺阁 2.56.1 的容器格式一致。

## 校验记录（2026-11-01）

- 页面产物与 `xbs_tool.py` 参考实现**逐字节一致**：次元姬 68,648 B、少年梦 16,784 B、合并 85,424 B。
- 香色 schema 校验：`PASS`，`ERROR_COUNT 0`、`WARNING_COUNT 0`、`SOURCE_COUNT 3`。
- 编辑器兼容检查：仅 `[MEDIUM] NEW_SCHEMA_WRAPPER`，与之前单源版本同一条已知提示。
- 真实 Chrome（iPhone UA）跑通：三个按钮联动正常、点击触发下载、下载文件与内存字节相同。

## 注意

- 页面不把任何凭证发出去；JWT / Token / 账号密码只写进用户本机的 `localStorage`。
- 换口令、换 JWT 之后必须重新生成再导入，导入时**同名覆盖**，书架与阅读进度不受影响。
- 生成出来的 `.xbs` 里含用户自己的凭证，别转给别人。
